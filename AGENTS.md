# AGENTS.md

## Project

Top-down bullet-hell shooter in the spirit of *Enter the Gungeon*, written in **Java 21** with **libGDX 1.13.5** (LWJGL3 desktop backend). Built with **Maven** (deliberately not Gradle — the owner knows Maven).

## Build & run

- Build: `mvn clean package`
- Run: `java -jar target/game-0.11.0-SNAPSHOT-jar-with-dependencies.jar` (the fat jar, not the thin one)
- Run from IDE: `com.trush.game.launcher.AppLauncher`
- Debug flags only work in a **dev build**: `mvn clean package -Pdev` (Maven filters `src/main/resources/dev.properties`; running from the IDE without filtering also counts as dev). A normal `mvn clean package` ignores them all. Flags (see `launcher/Dev`): `-Dfluffy.god=true`, `-Dfluffy.allGuns=true`, `-Dfluffy.gun=chomper` (start with that gun in hand), `-Dfluffy.items=all` (or `fluff_field,grenade`), `-Dfluffy.bossRoom=true` (a new story run from the menu starts at the boss), `-Dfluffy.retryBoss=true` (try again/restart goes back to the boss instead of floor 1), `-Dfluffy.keepSave=true` (continuing doesn't use up the save), `-Dfluffy.boss=haymaker` (force a boss), `-Dfluffy.floor=N` (start a story run on floor N; 2 = the town, 6 = the secret sea), `-Dfluffy.mimic=true` (every town/city combat room hides a mimic lamp), `-Dfluffy.blackChest=true` (every treasure chest - and a flawless boss's - is a black S chest), `-Dfluffy.slums=true` (a story run starts down in the Slums; with `-Dfluffy.bossRoom=true`, at its boss), `-Dfluffy.slumsWay=true` (with `-Dfluffy.floor=3`: start in the dead end with the burning drum), `-Dfluffy.undercity=true` (a story run starts in the Undercity), `-Dfluffy.win=true` (a story run opens on the victory screen; with `-Dfluffy.undercity=true` the normal ending), `-Dfluffy.fight=true` (start in the floor's deepest roomy fight, to try its enemies), `-Dfluffy.enemy=raccoon` (every story fight is just that kind - `StoryDirector.NAMES`, the Moon's `MOON_NAMES`: bunnies, asteroid, astronaut, alien), `-Dfluffy.trap=acid` / `pipes` (with `-Dfluffy.slums=true`: start in a trap room), `-Dfluffy.floor=6` or `-Dfluffy.sea=true` (a story run dives into the secret sea right away; with `-Dfluffy.floor=5` you surface on the clouds; with `-Dfluffy.bossRoom=true` too, straight into the Fluffy Shark's lair), `-Dfluffy.play=story` / `endless` / `home` (skip the main menu; home = the living room - handy for trying a floor: `-Dfluffy.play=story -Dfluffy.floor=5`), `-Dfluffy.startWave=N` and `-Dfluffy.layout=N` (endless), `-Dfluffy.shop=true` (a story run starts in the shop; endless opens the travelling stall before wave 1), `-Dfluffy.coins=N` (start with N coins), `-Dfluffy.rocket=N` (the living room's rocket shows as built by the first N of the family, not saved), `-Dfluffy.bossHp=N` (a story boss starts at N% health, to try its later phases), `-Dfluffy.moon=true` (a story run starts on the Moon; with `-Dfluffy.bossRoom=true`, at its boss), `-Dfluffy.play=ride` (the rocket ride first, then a story run). Read new flags through `Dev.flag`/`Dev.number`, never `System.getProperty`. Only `dev.properties` is filtered — never filter binary assets.

## Code map

- `launcher/ETGFanfic` — the `Game`; owns shared `batch`, `font`, `viewport`, `draw` (`gfx/Draw`), `sprites` (`gfx/Sprites`), `sfx` (`audio/Sfx`), `prefs` (best score/wave). Use `game.text(str, x, y, scale, color, Align.x)` for text.
- `screen/MainMenuScreen` - the title screen (over `screen/TitlePicture`, the owner's idea after ETG's castle: the story's road panning by - village, town, night city, skyscraper, the King's castle on its cloud; places past `ETGFanfic.getFurthestFloor` (prefs `furthestFloor`, set in `GameScreen.show` via `reachFloor`; any win counts as everywhere) are grey in mist with a "?"; the castle is stormy until a win, then bright with a rainbow; a shark fin once `Unlocks.foundSea`; a newly reached place sparkles with "NEW PLACE: ..." once - prefs `titleSeen`; the menu sits on the right under the castle, above the sea, `MenuList.setCenter`; every new win gets "KINGDOM SAVED N TIMES!" - prefs `titleWins`): NEW GAME (until the intro has been seen: the intro, then home) or CONTINUE (straight home), OPTIONS, QUIT. `screen/HubScreen` - the family's living room (like ETG's Breach; art `sprites/home.png`/`home.txt` from gen_sprites `home_sheet`: the baked `room` background + free-standing `sofa`/`armchair`/`lamp`/`plant` depth-sorted with the hero): walk up to a `Spot` and press E / A - the front door ("GO OUTSIDE?", or "CONTINUE THE TRIP?" with a `RunSave`: continue / start a new trip / stay home), the TV (endless; a saved trip stays saved), the bookshelf (the intro again, then home), the trophy shelf (wins, best score, best wave), the family's cardboard rocket in the bottom-right corner (the way to space, planned in ROADMAP: there from the first win over the Fluffy King; each hero who beats him in a story run adds a layer - `Unlocks.kingBeatenBy`, prefs `kingBeatenBy`, set in `ETGFanfic.addWin`, the Undercity's ending doesn't count; sprites `rocket_box/cone/fins/scarf/engine` from gen_sprites, all one size and stacked; finished = `Unlocks.rocketBuilt`: it rattles and puffs smoke; its panel lists who built what; once built, beating the Fluffy King in a story run lands it on the clouds beside the rainbow - `objects/Rocket` in `Room.rocket`, `GameWorld.landRocket` from `StoryDirector.clearRoom`, flown by `Rocket.pilotFor` (grandad, granny for grandad), prompt "WANT TO GO EVEN HIGHER?" - climbing in (`GameWorld.rocketBoarded`, `StoryDirector.boardedRocket`/`nextStage`) counts the win (`addWin`, `Unlocks.boardRocket` for the coming home console) and ends the floor on the stage clear screen ("THE KINGDOM IS SAVED!", BLAST OFF!), then `GameScreen.nextFloor` plays `screen/RocketRideScreen` (30 s: the rocket auto-fires, you steer round asteroids, bumps never hurt, nothing to collect; Esc skips) before the Moon); Esc / Start back to the title. Runs end back home (`GameScreen.toMenu` -> HubScreen, "GO HOME"). `screen/GameScreen` (story or endless) — input states (playing / paused / game over / stage clear / victory; game over and victory end on a `MenuList`: try / play again, go home, exit game - beating the boss of `Stage.lastFloor()` wins the run: confetti, score, `ETGFanfic.getWins()`, play again or menu; no save), camera shake (and zoom: a boss's `Enemy.viewZoom`), music crossfades, HUD + minimap; world overlays over the hero: RELOAD (magazine nearly empty, `Weapon.wantsReload`) / EMPTY hints and the Long Shot's laser sight; when every enemy left in a fight has been off screen for `LOST_DELAY` 1.2 s, red arrows at the screen edge point at each one (`updateLostEnemies`/`drawEnemyArrows`). When a boss appears (`activeBoss`, once per spawn) the camera first glides over to it (`BossCard.LEAD` 1 s, slow lerp `CAMERA_GLIDE`), then `screen/BossCard` shows an ETG-style introduction while the world holds still, then the camera glides back; when a boss dies the camera follows its death show and lingers on where it fell for `BOSS_FALL_HOLD` 2.2 s while its banner is up (`GameWorld.bossDeathSpot`). The card: a tilted band, a close-up via `Enemy.drawPortrait` (a fresh `Boss.create` instance; the Kaiju overrides it to draw just its head), "THE" + the name, and its line `Boss.quote()` typed out under it; any key / click / A / B skips (Esc too, instead of pausing). The victory screen shows `screen/EndingPicture` (picture-book style: the restored kingdom, the castle back on its cloud, the hero flying off on a cloud with a rainbow trail). All simulation lives in `world/GameWorld`.
- `save/RunSave` — between-floors save, like ETG: only offered on the stage clear screen after the boss (or when the window is closed there). Holds next floor number, score/kills, hearts, blanks, keys, coins, Baa-llo's grudge, guns + ammo (by name via `Weapon.byName` — register new guns there). Continue starts `StoryDirector(floor, ownedGuns)` on that floor's `Stage` (+0.15 difficulty and +25% regular-enemy health per floor via `GameWorld.setEnemyHealth`, applied in `spawnEnemy`; endless +4% health a wave up to +75%; bosses scale by their tier instead). Deleted when continued or when a new run starts. No saving mid-floor.
- Map: the HUD minimap and the big map (hold LT on the pad / M on the keyboard; the world pauses) share `GameScreen.drawRooms`, which also shows what's left in visited rooms (unopened chests as little chest shapes in tier colours, keys as yellow key shapes, every other item as an orange dot, the open exit in green). On the big map the player picks a visited room (stick / d-pad / arrows / mouse) and teleports there with A / Enter / click (`GameWorld.teleportTo`; not while the room is locked for a fight). The big map doesn't open during a fight (`Director.inFight`: a locked room / an endless wave) - a stray LT would hide the bullets.
- `screen/IntroScreen` — the opening story, a picture book of six pages (typewriter text under scenes drawn from the game's own art via `Enemy.drawPortrait`, hero/prop/gun sprites); plays before the first story run (prefs `seenIntro`), "THE STORY" in the main menu replays it; any key/click/A turns the page, Esc/B/Start skips.
- The family (`player/Hero`, the owner's idea): BOY (the hero), SISTER (ninja wannabe: 2 hearts, `rollReach` 1.3, starter `Weapon.throwingStars`), GRANNY (`walkSpeed` 0.9, starter `Weapon.pearlRevolver`, her cat `objects/Cat` - GameWorld `updateCat`: pads at her heels, leaps at the nearest enemy on screen every `COOLDOWN` and bites; `catPresent` when a fight ends, `GIFT_CHANCE`: half heart / blank / ammo / key), GRANDAD (`rollReach` 0.72, starter `Weapon.doubleBarrel` - meant to feel strong, he's earned by beating the King; `objects/GrandadVoice`: a wise-grumpy line in the Flufful's speech bubble `DELAY` 2.2 s after a boss falls, over the Flufful's; `Player.addWeapon` upgrades every new gun once, his starter too; locked until `Unlocks.grandad` = any win, set in `ETGFanfic.addWin`). `Hero.current` (prefs `hero`, `Hero.load` after `Unlocks.load`) is who `GameWorld` builds the `Player` as; `RunSave.hero` keeps the trip's hero. ## Conventions

- Plain Maven project — **no Spring Boot**; keep it out of the POM.
- Test dependencies (JUnit, Mockito) stay at `test` scope.
- The LWJGL3 backend extracts natives automatically — do not re-add `maven-nativedependencies-plugin` or `antrun` launch hacks (those were LWJGL2-era workarounds).
- Assets live under `src/main/resources/assets/` and are loaded with the `assets/` prefix, e.g. `new Texture("assets/sprites/player.png")`. Do not flatten assets into the classpath root.
- The shared font (`ETGFanfic.font`) is a FreeType-generated pixel font (Press Start 2P, Latin-only — no `∞` etc.) created once in `ETGFanfic.create()` and disposed in `ETGFanfic.dispose()`. Screens must use it, not create/dispose their own.
- Never call `setUseIntegerPositions(true)` on fonts — the world is only 7×5 units and rounding to integer positions collapses small text to nothing.
- World: `FitViewport(7, 5)` - the camera shows 7x5 units (`Arena.VIEW_W/H`); pixel art is 32 px per unit. Each room has its own geometry (`Room.arena`, an `Arena(cols, rows)`: walls, door gaps, layout grid; 13x8 = one screen); gameplay code uses the current room's `Arena.now` (set in `GameWorld.enterRoom`), code that builds/draws a specific room uses `room.arena`. `GameScreen.updateCamera` follows the player and leans toward the aim (and toward the boss in boss fights, always keeping the player well in view), clamped to the room (black beyond the walls); the HUD is drawn with a fixed camera in 7x5 screen units, world-space overlays (prompts, pad reticle) in `drawWorldOverlays`.
- Art is generated: `tools/gen_sprites.py` (hero, props + `props.txt` atlas, tilesets), `tools/gen_sfx.py`, `tools/music/tracks.py` (FluidSynth + GeneralUser GS soundfont from the Towards Dreams project; tracks: menu, village, town, city (room themes get darker floor by floor: folk-rock village, harmonic-minor galloping town, cold synth city with a tolling bell; endless switches village → town → city → tower → sky at waves 6, 11, 16 and 21), boss (the Fluffy King's theme), boss_village, boss_town, boss_city, tower (lift-music intro, then office rock), boss_tower (orchestral, on the roof), sea / boss_sea (the secret sea and its shark), slums ("Back Alley Blues", the secret Slums: walking bass, Rhodes, muted trumpet), boss_slums ("Gutter Groove", slap bass, organ, brass), undercity ("Down Where the King Sleeps": a crooked music-box lullaby, dripping pizzicato, a bad king's fanfare), boss_undercity ("The False King's March": oom-pah tuba, snare rolls, a nasal oboe fanfare), sky ("Silver Lining", the clouds: harp, celesta, choir, then the band; their boss is the Fluffy King, so the boss track is his "boss") - `Stage.bossMusic`, `Boss.music()`; falls back to ffmpeg's built-in vorbis encoder when libvorbis is missing). Edit the scripts and regenerate rather than hand-editing the PNG/WAV/OGG files. Use Nearest filtering for pixel art.
- The player collides with a small feet box (`Player.feetRect`), not the sprite; enemies are circles pushed out of walls/props (`GameWorld.pushOutOfSolids`).
- Enemies, bullets, guns and pickups are still placeholder art drawn with `gfx/Draw` (shapes on the SpriteBatch, no ShapeRenderer). Replace a `drawBody` with sprites when real art exists; keep hitboxes (`radius`) independent of art.
- Bullets (and enemy line of sight, lasers) are stopped by `Prop.bulletRect(sprites, northbound)`: a bullet going up the screen hits the whole tall part (up to just below the sprite top, so standing behind a pillar covers you); going down or sideways it only hits the footprint. Street lamps block with a slim 0.14 post and are breakable (30 hp). Bullets touching the player's visible body only break on it when cover is really between them (`GameWorld.coverBetween`) - never all-round immunity. Movement still uses the footprint (`solid`). Tests that mock libGDX classes need `MockMakers.SUBCLASS` (inline mocking fails on newer JDKs).
- Boss bullets: everything a boss fires during its `behave` is restyled by `GameWorld.styleBossBullets` - 1.3x bigger and 0.85x slower, with `Bullet.hitScale` keeping the hitbox the same size (patterns read better, gaps don't shrink). Regular enemies' bullets are unchanged.
- Collisions are circle-vs-circle. The player's hitbox is a small circle around the belly (`Player.hitboxY()`, `HITBOX_RADIUS`), not the sprite rectangle.
- Don't remove from `enemyBullets` while it may be iterated — mark `alive = false` and let `GameWorld` sweep (taking damage and blanks clear bullets mid-update).
- Killed enemies move from `enemies` to `GameWorld.dying` and play their death there (`Enemy.updateDeath`/`drawDying`: regular ones topple away from the shot and shrink, pit fallers spin down, bosses get slow motion, ~2 s of explosions and a big blast); the room only clears when `GameWorld.bossDying()` is false. Code that needs a boss gone (rewards) waits for that.
- Spawn enemies via `GameWorld.spawnEnemy` (goes through a pending list), never by adding to `enemies` directly during update.
- Sound effects: `assets/sfx/*.wav` are generated by `tools/gen_sfx.py`; register new ones in `audio/Sfx` (the angels use `swish` / `twang`, birds `flap`, coins `coin`, the shop `kaching` and Baa-llo `baa`; `whistle` is the Evil Train's, `hiss` the city's burning drum going out, `siren` the Walking Building's alarm before its bullet curtain, `howl` the alley dog's). `sfx/death.wav` is `assets/die-sound.mp3` with its leading silence cut (needs ffmpeg), so it lines up with the death animation; `body_fall` plays when the hero hits the floor. Regenerating rewrites every WAV — only commit the ones whose audio actually changed.
- Lombok (`@Getter`, `@Data`) is used; keep the annotation processor path in `maven-compiler-plugin`.
- Commit and push after every finished change (once it builds and tests pass): one change per commit, with a sensible conventional message (`feat: ...`, `fix: ...`), then `git push`. Don't leave work uncommitted.
- Commit with `git -c core.autocrlf=input` from Linux shells: some older files have CRLF line endings on disk and the owner's Mac git normalizes them.
- Docs: `README.md` is for players and stays spoiler-free - the secret floor and anything that gives it away (the Flufful's unlock, the Flippers, sea creatures) go in its collapsed "Spoilers" `<details>` block. The README only sums up guns and items; their full list, dev flags, asset scripts and room layouts live in `DEVELOPING.md` (add new guns/items there) (keep its flag list in step with `launcher/Dev`); the jar name appears in README, DEVELOPING and here - bump all three on a version change.
- The only loose files in `assets/` are `drop.mp3` (the pickup sound) and `die-sound.mp3` (the source of `sfx/death.wav`); everything else sits in its folder (`sprites`, `tiles`, `sfx`, `music`, `fonts`). The window icons are the stock `libgdx*.png` in the resources root.
